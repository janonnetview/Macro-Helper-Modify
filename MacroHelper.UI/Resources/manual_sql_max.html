Famílias de tabelas de documento

Foram localizadas mais de 60 tabelas ligadas a documentos, com nomes muito parecidos entre si. As que aparecem nos atendimentos:

Verificar antes de usar
  • Os documentos de origem citam TbDocumento, TbDocumentos, tbDocumento e tbDocumentos em pontos diferentes, sem deixar claro se são quatro tabelas, duas, ou variações de escrita da mesma. Rode a consulta CAT-02 com LIKE '%Documento%' e fixe aqui os nomes reais.

Armadilhas conhecidas

Coisas que já custaram tempo ou geraram resultado errado. Vale reler antes de entregar conferência para cliente.

NOT IN engole os NULL

WHERE StatusPublicacao NOT IN (1,4,5) não traz as publicações com status NULL. Comparar qualquer coisa com NULL dá desconhecido, e o registro é descartado. Como NULL é um dos valores que existem de fato na TbPublicacaoWS, essa consulta esconde justamente parte do que se quer investigar.

Para incluir os nulos: WHERE (StatusPublicacao NOT IN (1,4,5) OR StatusPublicacao IS NULL).

Função na coluna derruba o índice

WHERE CAST(Data AS DATE) = '2026-07-14' obriga o banco a calcular o CAST em cada linha antes de comparar, então nenhum índice sobre Data é aproveitado. O intervalo faz o mesmo trabalho e continua indexável:

WHERE Data >= '2026-07-14' AND Data < '2026-07-15'

Vale a mesma lógica para YEAR(Data) = 2024 — troque por >= '2024-01-01' AND < '2025-01-01'.

Comparação de CNJ é textual

Máscara diferente entre planilha e banco (com pontuação de um lado, só dígitos do outro, ou espaço sobrando) aparece como DIVERGENTE mesmo com os dígitos idênticos. Quando a divergência for suspeita, normalize os dois lados para só dígitos antes de concluir.

IS NOT NULL redundante em comparação de data

Em WHERE pub.Data > p.DtEncerramento, as pastas sem encerramento já ficam de fora sozinhas, porque comparar com NULL nunca é verdadeiro. Escrever DtEncerramento IS NOT NULL junto não muda o resultado — mas deixa a intenção explícita para quem ler depois. As duas versões circulam na documentação; não é divergência.

Uma pasta, várias linhas

Em tbSpProcessoPedidos cada linha é um pedido. Uma pasta com oito pedidos volta oito vezes. Não existe concatenação por ponto e vírgula — quem espera uma linha por pasta precisa de CTE com agregação ou STUFF + FOR XML PATH.

Padrões que se repetem

Filtro por período

WHERE Data >= '2026-01-01' AND Data < '2027-01-01' — limite inferior fechado, superior aberto. Evita o problema de hora no último dia.

Exploração antes da consulta boa

SELECT TOP 20 * primeiro para ver o formato dos dados, depois a consulta com as colunas certas. Evita puxar milhões de linhas por engano.

LEFT JOIN por padrão em conferência

Em validação de lista de cliente, LEFT JOIN é quase sempre o certo: o que não existe no banco precisa aparecer como "não encontrado", não sumir. INNER JOIN só quando o relacionamento for obrigatório para a pergunta fazer sentido.

Registros ativos

Status = 1 ou StatusRegistro = 1, dependendo da tabela. Em tbPartesProcessos é StatusRegistro.

Concatenar linhas em uma coluna

STUFF((SELECT ... FOR XML PATH('')),1,0,'') — usado para juntar todas as partes de um processo em uma célula só.

Aliases curtos

p = TbProcessos · pr = TbPrazos · pub = TbPublicacaoWS · d = TbDiligencias · sp = tbSpProcessoPedidos · gm = TbGrupoMateria · tp = TbTipoProcesso · ap = TbAssuntoPedido

NOLOCK

Usado só em leitura para análise. Aceita leitura suja: pode trazer linha que ainda vai sofrer rollback. Não usar em número que vá para relatório oficial do cliente.
